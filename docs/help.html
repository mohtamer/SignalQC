SignalQC user guide

Developed by Mohamed T. Hussein & Tadahiro Kishida.

Run the included example

  1. Select Process existing HDF5 files.
  2. In Input data, click Use included sample inputs.
  3. Click Save project and choose a new empty folder outside test.
  4. Open Review and run, scan the inputs, review the inventory and start processing.
  5. When finished, open Results → Compare sample results and select your new project folder.

The May 2013 example contains 18 components from three stations. All 18 pass Stage 1; the recorded sanity-check outcomes are 12 passes and 6 failures. A scientific QC failure is distinct from a processing error. Reference outputs are stored separately in test/reference_results.

The sample button loads the recorded 0.3 Hz high-pass fallback; the normal new-project default is 0.1 Hz. Both use an 8 Hz low-pass minimum/fallback. Keep the sample settings unchanged when comparing results.

Catalogue and station tables

Small examples are in test/metadata. The public edition does not load a hidden station database, catalogue or response library. Select your own files for conversion. The selected catalogue is read at scan/run time, so save Excel edits before scanning.

Event columns: event_id, origin_time (UTC), latitude, longitude (decimal degrees), depth_km, magnitude, optional magnitude_type and file name. Separate year/month/day/hour/minute/second columns are also supported.

Station columns: network, station, latitude, longitude, elevation_m, and bits where known. Location, channel and validity dates can distinguish sensor epochs. Hypocentral distance excludes station elevation.

Common headings and unambiguous quantities such as “10 km” are recognized. Use Map event columns or Map station columns when needed. Ambiguous values require review. Missing optional labels are tolerated, but sampling information and waveform units must be meaningful.

Raw files are matched to catalogue filenames first, ignoring supported filename extensions. Unmatched files use the event window from 2 minutes before to 1 hour after trace start. Multiple matching events each receive the full untrimmed waveform.

Processing and quality outcomes

Stage 1 applies the original voting and early-stopping rules. Unevaluated scores can therefore be blank. Stage 2 selects corners, filters, trims and corrects the baseline. Guo runs in Python; MATLAB is unnecessary and USGS is disabled. Stage 3 reports each enabled check; check 5 is off by default. Disabled/unavailable checks are not passes.

Start with two workers, then increase gradually while monitoring memory. Keep active HDF5 work local when possible. Do not process the same files from two computers simultaneously.

Results and recovery

Results include one consolidated processing workbook per input/group, a processed HDF5 ending in processed_2 by default, and optional figures. Select table rows to view linked waveforms or figures.

To resume, choose Open project and select project.json, then rescan and run with Resume enabled. Keep outputs and checkpoints together. Use the pause control for a safe stop.

Use Results → Browse existing results folder to view older outputs. View sample reference results opens the supplied reference. The comparison checks identifiers/decisions exactly and numerical values with relative tolerance 10−7 and absolute tolerance 10−10; paths and timestamps are excluded.

Opening SignalQC on another computer

The portable ZIP contains Python, R and packages. Extract all files and open Launch SignalQC.cmd (or the normal Python launcher). For installed, approved interpreters, use Launch SignalQC - Installed Python and R.py; the first setup needs internet. Choose the actual python.exe and Rscript.exe, not Start Menu shortcuts. PyCharm and MATLAB are unnecessary. Organizational restrictions still apply.

The folder's README.md contains the full guide, setup requirements, input definitions and troubleshooting.
